\paragraph{Engineering standards} TypeScript strict with schema validation at every boundary; persistence behind two ports with in-memory twins so the test suite needs no network; structured logs keyed by the item's reference; formatting and validation before every infrastructure commit; small, single-purpose commits with imperative messages so the history reads as a change log. Infrastructure as code and GitOps are applied uniformly, making the audit trail in Sec.~\ref{sec:arch} complete rather than partial.

\paragraph{Embedding contract} A site adopts \ffrs{} with one tag:
\begin{lstlisting}
<script src="/assets/js/ffrs-widget.js"
  data-endpoint="/api/feedback" data-site="example.org"
  data-turnstile="<sitekey>" data-screenshot="bug" defer></script>
\end{lstlisting}
and a function deployment configured by environment variables (tracker repository, mail sender, bucket). Everything site-specific is an attribute or a variable.

\paragraph{Reproducing the metrics} \texttt{npm run metrics} and \texttt{npm run export} in \texttt{ffrs-api} read the public tracker and emit per-week metrics and anonymised per-item rows (no body, e-mail or screenshot). The CSVs used in Sec.~\ref{sec:eval} are committed under \texttt{data/} in the paper repository.
